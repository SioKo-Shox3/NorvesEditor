# ターンを返す前に「やれることが残っていないか」を自分で確かめる

## 何が起きたか

主題を1つ閉じるたびに、検証結果と残課題を報告してターンをユーザーへ返していた。
ユーザーからの訂正: 「作業残した状態でこっちにターン回さないでください。やれることは
のこってるでしょ? 全部終わらせてください」。

実際、返した時点で次の候補は自分で書き出していた(`PROGRESS.md` の Next)。評価者の
non-blocking 指摘も「残課題」として置いたままだった。手が止まっていたのではなく、
区切りがついたから報告した、というだけだった。

## なぜ間違いか

ユーザーがターンを受け取るのは、**ユーザーにしか決められないことがある**ときだけでよい。
「区切りがついた」は報告の理由にはなるが、ターンを返す理由にはならない。次の候補を自分で
書き出せているなら、それは自分で判断できる作業であって、渡す必要がない。

渡してしまうと、ユーザーは「続けて」と打つためだけに手を動かすことになる。

## 次から

ターンを返す前に確かめる:

1. `TASKS.md` に未完は無いか。無いなら `PROGRESS.md` の Next は空か。
2. 評価者の指摘で、自分で直せるものが残っていないか(non-blocking も、実害があるなら直す)。
3. 触った範囲に、テストが緑でも見た目や操作が壊れている場所が残っていないか。
4. 1〜3 が全部片付いていて、なお残るのが「ユーザーにしか決められない判断」「この環境では
   できない検証」だけになったか。

4 に達していないならターンを返さず続ける。報告は区切りごとにしてよいが、報告と
ターンを返すことは別。
