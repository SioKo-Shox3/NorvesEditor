# 編集の層・言語モデルの口（MCP）・資産の編集・決定的な撮影 要件と設計

基準日: 2026-10-02。初稿のコード基準は NorvesEditor `700dfa8` と NorvesLib `01fda10`。
E0〜E3 の設計基準は NorvesEditor `700dfa8`。作業ブランチは、このコミットから分岐した `feature/editor-mcp-edit-layer`。

## 1. この文書について

- 目的：NorvesEditor を、エンジンの汎用 GUI と MCP のプロトコル抽象化層として使うための要件と作業を定める。
- 土台：取り消しの履歴と編集の層を Rust バックエンドへ移し、画面と言語モデルの両方が同じ編集サービスと履歴を使う。
- 範囲：NorvesEditor の側（Rust のバックエンド、画面、Bridge の仕様と C++ の SDK、モックのエンジン）と、それと対になる NorvesLib の側（Bridge のアダプタ）。NorvesLib の側の作業は、NorvesLib のゲーム機能ロードマップ（NorvesLib の `Docs/Plans/GameFeatureRoadmap.md`）への追加 GR137 として、作者が NorvesLib の作業者に渡す。文中の GR で始まる番号は、そのロードマップの要件の番号。
- 要件の番号：NE01〜NE22。
- 状態：E0〜E3（NE01〜NE14）の設計は2026-10-03に承認済み。ADR 0010 / 0011 に設計判断を記録し、実装単位・対象パス・検証条件は `TASKS.md` に定める。E4 と関連要件（NE15〜NE22）は今回の実装承認範囲外。
- 今回の実装範囲: E0〜E3（NE01〜NE14）。E4（NE15〜NE20）と関連（NE21、NE22）は参照として残し、今回の `TASKS.md` には入れない。NorvesLib のコードは変更しない。
- 承認済みの設計資料: ADR 0010 / 0011、E0〜E3 の29タスク、取り消し試験の対応表、11〜12章の設計・依存一覧。2026-10-03 に承認済み。MyWorkflow のガイド正本2本の同期は MCP-029 として別に実施する。

## 2. 作者の判断（2026-10-02）

- NorvesEditor を、ただのエンジンの汎用 GUI ではなく、エンジンとの MCP のようなプロトコルの抽象化層としても機能するように拡張するのがよいと考えている。
- 取り消しの履歴と編集の層は (b) で進める。Rust のバックエンドへ移し、画面と言語モデルの両方がそこを通す。
- 言語モデルの口の書き込みの既定のモードは、読み取りのみ。
- 資産は、実際はクックされてバイナリで読まれる。文字列は、資産と言語モデルの間で MCP のようなプロトコルで受け渡せる、というだけにとどめる。それをエフェクト専用にするのが合っているかは疑問。
- 言語モデルにエフェクトを組み立てさせても、品質が担保されるかは疑問。言語モデルが組んだエフェクトは、そのまま出すには品質が厳しい。見た目はシェーダーと使うテクスチャ次第。
- この文書は、NorvesEditor の `docs` に置く。

## 3. 目指す使い方（案）

1. 作者が NorvesEditor を起動し、エンジンにつなぐ。Settings で言語モデルの口（MCP）を有効にする（既定は無効）。
2. Claude Code などの言語モデルの道具が、MCP でエディタにつなぐ。使える道具は、つないでいるエンジンが広告する能力で決まる。
3. 書き込みのモードは、既定では読み取りのみ。作者が書き込みを許したときだけ、言語モデルは型と値の範囲（スキーマ）を読んで、シーンや資産の値を変える。変更はエディタの編集の層を通り、出どころ「言語モデル」の付いた1つのまとまりとして履歴に積まれ、画面の Outliner と Inspector にもすぐ出る。
4. 言語モデルは、時刻と乱数を固定した撮影（連番を1枚に並べた画像）を受け取り、それを見て値を直す。
5. 作者は、動いているエンジンとエディタの画面で結果を見る。気に入らなければ、まとまりごと取り消す。よければ保存する。見た目の良し悪しを決めるのは作者で、言語モデルは下書きと数値の調整の手伝いにとどまる。

### 4.1 NorvesEditor（`700dfa8`）

2026-10-02 に HEAD が `700dfa8` であることと、以下のファイル・規則を再照合した。
`chore/editor-small-fixes` は、取得済みの `origin/main`（`872e406`）に未統合。

1. **構成と所有**：Tauri のデスクトップアプリ。画面（TypeScript）は Tauri のコマンドとイベントだけを使い、生の WebSocket に触らない。Bridge の接続とエンジンのプロセスは Rust のバックエンドが持つ（`docs/architecture.md`、`CLAUDE.md` の絶対規則 1〜3）。エディタはエンジンに依存しない作りで、NorvesLib 固有のことはアダプタに置く（`docs/vision.md`）。
2. **危険地帯**：プロトコルのスキーマと互換、Tauri のプロセスとセキュリティの権限、Rust の async のタスクの寿命、WebSocket の転送と再接続、C++ の SDK の公開 API、バッファとメモリの所有、スレッドの親和性、NorvesLib のアダプタ、ビューポートの方針。ここを触る変更は評価者を必ず通し、コミットの本文を書く（`CLAUDE.md` の絶対規則 5）。この文書の要件の多くが当たる。
3. **プロトコル**：版は 0.2。WebSocket と JSON。要求・応答・イベントの封筒（JSON-RPC に似るが、厳密には従わない）。任意の機能は能力（capability）のトークンで接続ごとに交渉し、広告されていない機能のメソッドは `METHOD_NOT_SUPPORTED` を返す（`bridge/spec/docs/protocol-overview.md`、`capabilities.md`、`error-model.md`）。能力の追加は互換を壊さない。メソッドなどを足すときは、schema、positive の fixture、要れば negative の fixture、Rust・TypeScript・C++ の検証を同じ段に入れる。互換を壊す変更は、ADR か移行の注記が要る（`docs/agent-guide/protocol-schema.md`）。
4. **今の手順**：仕様に定義のあるメソッドは、`bridge.hello`、`bridge.getCapabilities`、`engine.getStatus`、`engine.launchInfo`、`runtime.play`、`runtime.pause`、`runtime.stop`、`runtime.focusViewport`、`log.subscribe`、`log.unsubscribe`、`scene.getTree`、`scene.createObject`、`scene.deleteObject`、`scene.reparentObject`、`scene.duplicateObject`、`object.getSnapshot`、`object.setProperty`、`schema.getSnapshot`、`component.add`、`component.remove`、`asset.resolve`、`asset.getManifest`、`asset.reloadManifest`、`viewport.getThumbnail`（`bridge/spec/schema/methods/`）。イベントは、`bridge.connected`、`bridge.disconnected`、`engine.statusChanged`、`engine.processExited`、`runtime.stateChanged`、`viewport.stateChanged`、`log.message`、`error.reported`、`scene.treeChanged`、`object.changed`。シーンや資産を保存する手順は無い。
5. **エンジンは1接続だけ**：エンジン側の SDK は、同時に1つのエディタだけを受け付け、2つ目の接続は拒否する（`bridge/cpp/engine-sdk/src/ws_server_transport.cpp:44-47`）。エディタが接続している間、言語モデルの道具はエンジンに直接つなげない。
6. **ハンドラは同期**：エンジン側の SDK のアダプタ（`bridge/cpp/engine-sdk/include/Norves/Bridge/adapter.hpp:43` の `IBridgeEngineAdapter`）は、ハンドラが同期で値を返す形（`Result<JsonValue, BridgeError>`）。任意のメソッドは、既定で `not_supported` を返す（同ファイルの `:99` 以降）。何フレームもかかる処理を、1つの応答で返す形は無い。
7. **大きなデータ**：Bridge は制御の経路で、大きなデータの経路ではない。大きなデータの経路を足すときは、先に方式を文書にする。画面の縮小画像は PNG で最大 640x360、256 KiB、取りに行く方式で毎秒1回まで（`docs/memory-buffer-policy.md`）。
8. **取り消し（今の作り）**：
   - 履歴は画面の側の状態にある（`apps/editor/src/state/store.ts:289` の `undoStack`、`:296` の `redoStack`）。記録の種類は4つ（`:110` の `SceneEditCommand`：作る、複製、親の付け替え、値の設定）。値の設定の記録は、旧値と新値を持つ。
   - 記録は、公開の編集の手順が `accepted:true` を受けたときだけ（`useBridge.ts:697` 以降の各入口）。`store.ts:503` はアクションの定義、実際の push は `:1124` の reducer。作る・複製は `newId` も必要。旧値が無い設定は適用するが記録しない。旧値と新値が同じ設定は記録しない（`propertyValuesEqual`）。比較は `JSON.stringify` であり、同じ値でもオブジェクトのキー順が違えば別扱いになる。新しい記録は、やり直しの列を空にする。
   - 取り消しとやり直しは `apps/editor/src/hooks/useBridge.ts:1225` と `:1302`。公開の手順を通さず、逆の操作を直接出す。二重押しを防ぐ印がある。作る・複製のやり直しでは、新しく振られた ID で記録を書き換える。逆の操作が失敗したら、その記録を捨ててエラーを出す。
   - 値の設定の旧値は、発行直前に画面の store の `objectSnapshot` から取る（`useBridge.ts:1022-1026`）。選択中のコンポーネントの値など、このスナップショットに旧値が無い場合は現在も履歴に入らない。
   - 消すは取り消せない。成功したら履歴を全部捨てる（`useBridge.ts:742-746`）。消した部分木を作り直すと ObjectId が振り直されるため（`docs/scene-structure-editing-plan.md:177`）。
   - コンポーネントの取り外しは履歴に入らない。外すと値が戻らないので、画面が確認を出す（`apps/editor/src/components/PropertyInspectorPanel.tsx:325-331`）。
   - 切断とエンジンの終了で履歴を捨てる。ワークスペースを閉じても履歴は残す（`store.ts` の注記）。
   - Ctrl+Z / Ctrl+Y は `apps/editor/src/hooks/useUndoRedoKeybindings.ts`、ボタンは `apps/editor/src/components/shell/ToolbarActions.tsx`。
9. **Rust のバックエンド**：`BridgeState`（`apps/editor/src-tauri/src/bridge_state.rs:116`）は、tokio の Mutex で接続の段階を持ち、要求の ID と接続の世代を数える。「I/O を伴う await をまたいでロックを持たない」が規則（同ファイルの冒頭の注記）。メソッドの呼び出しは `send_method`（`:489`）で、要求ごとに時間切れがある。Tauri のコマンドは `lib.rs:51-84` で登録し、名前は `scripts/check-protocol-names.mjs` で照合する（`PROGRESS.md` の記録では、`2607fd4` の時点でコマンド 32、イベント 11）。

11. **型のスキーマ**：`typeDescriptor`（`bridge/spec/schema/common.schema.json:117-143`）は、型の名前、種類、作れるか、プロパティの定義を持つ。値の範囲・単位・既定値・説明と、呼べる関数は無い。

### 4.3 外のもの

- [公式 Rust SDK](https://github.com/modelcontextprotocol/rust-sdk) は、調査時点の公開版 `rmcp 3.5.0`、MSRV 1.88。`StreamableHttpService` と `transport-streamable-http-server` を提供する。エディタの MSRV 1.96 の範囲内。
- [MCP 2026-07-28 の Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) では、Origin が存在して不正なら 403。localhost への bind と認証も必要。2026-07-28 は要求ごとのメタデータを使う stateless 方式で、旧版の HTTP セッション / GET の独立 SSE とは異なる。接続・通知の扱いを旧版の前提で実装しない。
- 今回は SDK の対応する 2026-07-28 と legacy 2025-11-25 をそれぞれ試験する。現行版はアプリが `accepted_subscription_filter` と `listen` を実装し、`SubscriptionSink` へ道具一覧の変更を流す。旧版はセッションの peer へ `notify_tool_list_changed` を送る。SDK の既定だけでは購読は有効にならない。試験クライアントは現行版の `Discover` と旧版の `Initialize` を明示し、通常の `.serve()` だけで両版を試験したと扱わない。

## 6. 要件

### NE01 設計の記録（ADR と層の境界）

- **決定**：2026-10-03に承認済み。判断の正本は [ADR 0010](adr/0010-backend-edit-service-and-history.md) と [ADR 0011](adr/0011-local-mcp-interface.md)。
  - UI と MCP の編集・取り消し・やり直し・実行制御は、Rust 編集サービスの受付順の列と履歴を共有する。履歴は Bridge の接続世代に結び付ける。
  - MCP は Rust バックエンド内のローカル Streamable HTTP サーバーとし、127.0.0.1 のみで待ち受ける。既定で無効、既定ポートは49770、書き込みの初期モードは読み取りのみとする。
  - MCP の認証・Origin/Host 検証・道具一覧・許可・確認は編集サービスから分離する。読み取りは既存の Bridge 照会を使い、書き込みは編集サービスへ渡す。エンジンのプロセス操作と設定は公開しない。
  - `docs/architecture.md` は編集サービス・MCP サーバー・Rust バックエンド・画面・Bridge 各層の所有者と境界を記録する。MyWorkflow 管理下のガイド正本2本は MCP-029 で同期し、このタスクの先行条件にしない。
- **完了条件**：ADR 2本が承認済みの判断を記録し、`docs/architecture.md` の層と所有者が一致している。評価を受ける。
- **規模**：S。

### NE02 編集のサービス（Rust のバックエンド）

- **内容**：バックエンドに、編集のサービスを置く（モジュールの名前は案：`apps/editor/src-tauri/src/edit_service.rs`）。
  - シーンの編集（作る、複製する、親を付け替える、値を設定する、消す、コンポーネントを付ける・外す）を、このサービスの手順として持つ。画面の Tauri コマンドと MCP の道具の両方が、ここを呼ぶ。
  - サービスは、編集・取り消し・やり直しを1件ずつ、来た順に実行する（作業の列を持つ tokio のタスクか、それに相当する直列化）。今の画面の「二重押しを防ぐ印」を、入口が2つになっても成り立つ形にする。
  - Bridge の呼び出しは今の `send_method` を使い、「I/O を伴う await をまたいでロックを持たない」規則を守る。
  - 履歴は接続の世代と結び付け、世代が変わったら捨てる。
- **根拠**：前提 4.1 の 8 と 9。
- **完了条件の案**：Rust の試験で、(1) 2つの入口から同時に来た編集が、来た順に1件ずつ実行される、(2) 取り消しの実行中に来た編集は、取り消しが終わってから実行される、(3) 接続の世代が変わると履歴が空になる、(4) Bridge の呼び出しの間にロックを持たない。
- **規模**：M。

### NE03 今の取り消しの規則をそのまま移す

- **内容**：画面の側にある今の規則を、変えずにバックエンドの履歴へ移す。
  1. 記録するのは `accepted:true` の編集だけ。
  2. 旧値と新値が同じ設定は記録しない。
  3. 新しい記録は、やり直しの列を空にする。
  4. 取り消しは、逆の操作を直接出す（公開の手順を通さず、履歴に積まない）。作る・複製の取り消しは消す。親の付け替えの取り消しは元の親へ戻す（シーンの根の直下は「親なし」にそろえる）。値の設定の取り消しは旧値の設定。
  5. 作る・複製のやり直しでは、新しく振られた ID で記録を書き換える。
  6. 現行と同じ単発の取り消し・やり直しで、逆の操作が失敗したら、その記録を捨ててエラーを出す。複数編集のまとまりでの失敗は NE06 の規則を使う。
  7. 消すは取り消せない。成功したら履歴を全部捨てる（NE21 が入るまで）。
  8. 切断とエンジンの終了で履歴を捨てる。ワークスペースを閉じても履歴は残す。
  9. 値の設定の旧値：画面からの設定は、画面が持つスナップショットの値と、その値を見た適用改訂を渡す。捕捉後に共通列が同じ対象へ適用した値があれば、その値を旧値にする。後続のエンジンliveイベントだけでは捕捉値を上書きしない。言語モデルからの設定は、NE15 が入るまで「設定の直前に `object.getSnapshot` で読んだ値」を旧値にする。エンジン自身の更新によるずれは NE15 でなくす。
- **根拠**：前提 4.1 の 8。
- **完了条件の案**：上の 1〜9 を1件ずつ確かめる Rust の試験がある。今の vitest の取り消しの試験が確かめている振る舞いと、新しい Rust の試験の対応表を作り、漏れが無い。対応表は `docs/mcp-undo-test-mapping.md`。
- **規模**：M。

### NE04 画面を、バックエンドの履歴の表示に切り替える

- **内容**：

- **完了条件の案**：`pnpm -C apps/editor typecheck` と `test` が通る。ボタンの有効・無効が、履歴のイベントで変わる試験がある。画面から見た取り消しの振る舞いが変わらない（既存の試験が、模型の差し替えだけで通る）。
- **規模**：M。

### NE05 編集の結果を画面へ知らせる

- **内容**：編集のサービスは、適用した編集ごとに（出どころを問わず）Tauri のイベントを出す。中身は、対象の ID、プロパティの名前、適用後の値、作られた ID、出どころ、まとまりの ID。画面の Outliner と Inspector は、このイベントで表示を更新する。エンジンのライブ更新のイベント（`scene.treeChanged`、`object.changed`）は確実ではない（`protocol-overview.md` で best-effort）ので、言語モデルの編集が画面に出ることを、それに頼らない。
- **完了条件の案**：画面の外（バックエンドの試験の入口）から来た値の設定が、Inspector の値と Outliner に出る vitest がある。
- **規模**：S〜M。

### NE06 操作のまとまりと出どころ

- **内容**：
  - 履歴の1件を「まとまり」にする。まとまりは、中に複数の編集、名前（例：「言語モデル：火花の色を調整（12件）」）、出どころ（人、言語モデル）、時刻を持つ。
  - 取り消しは、まとまりの中を逆順に戻す。やり直しは順に戻す。
  - 画面の1回の操作は、1件のまとまり（今と同じ粒度）。
  - 複数編集のまとまりの取り消し・やり直しが途中で失敗したら、成功済みの位置と未処理部分を記録して止める。同じまとまりを先頭に残し、再試行は未処理部分から行う。作者は再試行か破棄を選ぶ。保留中は新しい書き込みを拒否する。破棄は実際の状態を戻さないことを表示する。
  - 通常の編集の途中で失敗したら打ち切り、成功済みの編集だけを履歴に残す。画面の単発操作の失敗時は NE03 の 6 を保つ。
- **完了条件の案**：3件のまとまりが、1回の取り消しで全部戻る試験と、途中で失敗したときの試験がある。
- **規模**：S〜M。

### NE07 MCP のサーバー

- **内容**：
  - 公式の Rust の SDK（rmcp）の Streamable HTTP のサーバーを、Rust のバックエンドで動かす。
  - 127.0.0.1 だけで待ち受ける。Origin の見出しを検証し、不正なら 403 を返す（MCP の仕様の要求）。
  - トークンで認証する。トークンはエディタが作り、アプリの設定のディレクトリに置く（リポジトリには入れない）。Settings で表示と作り直しができる。
  - 既定は無効。Settings で有効にする。ポートは設定でき、既定値を持つ（値は案）。使用中なら画面にエラーを出す。
  - アプリの終了で止める（今の「アプリの終了でエンジンを止める」フックと同じ場所で）。
  - 新しい依存（rmcp と、その HTTP の層）は、依存の追加として計画のレビューに出す。
  - 接続の仕方（案）：Claude Code なら `claude mcp add --transport http <名前> http://127.0.0.1:<ポート>/mcp --header "Authorization: Bearer <トークン>"`。トークンの設定は作者が行う。
- **根拠**：前提 4.1 の 5、15、16、4.3。
- **完了条件の案**：無効のときはポートが開かない。127.0.0.1 以外で待ち受けない。Origin が不正なら 403。トークンが無い・違うなら拒否。`tools/list` が返る。ポートが使用中ならエラーが画面に出る。
- **規模**：M。

### NE08 道具の一覧を、能力と仕様から作る

- **内容**：
  - 道具は、接続中のエンジンの実効の能力にある機能だけを出す。接続・切断・再接続で一覧を作り直し、`notifications/tools/list_changed` を送る（サーバーの能力で `tools.listChanged` を宣言）。
  - 道具の入力の定義（JSON Schema）は、`bridge/spec/schema/methods/*.params.schema.json` をそのまま使う。MCP の入力の定義も JSON Schema なので、二重に書かない。
  - Bridge 書き込み道具では MCP 固有の外枠として `params` と任意の `groupId` を定義し、Bridge の `params` schema は埋め込みspecと同じ意味を保つ。ページング・ログ・履歴・名前付きまとまりなどMCP固有の入力は、それぞれ独自schemaを明示する。
  - schema検証は埋め込み済みの仕様だけで行い、外部のHTTP/file schemaを取得しない。未対応の参照は道具の公開と入力検証の両方で拒否する。
  - 道具の名前と説明に、エンジンに固有の名前を入れない。
- **完了条件の案**：能力の無い機能の道具が出ない試験。道具の入力の定義が、仕様の params の定義と一致する試験。切断で一覧が変わり、通知が出る試験。
- **規模**：S〜M。

### NE09 読み取りの道具

- **内容**：
  - 道具：エンジンの状態と能力、シーンのツリー、オブジェクトのスナップショット、型のスキーマ、資産の一覧と解決、最近のログ（NE10）、縮小画像（今の `viewport.getThumbnail`）。
  - 言語モデルの文脈の量を守るため、ツリーとスナップショットは大きさの上限を持ち、超えたら「どこで切ったか」を書いて、続きを取れるようにする。`scene.getTree` の `rootId` と `maxDepth` は仕様にあるが、NorvesLib のアダプタは無視して全体を返すので、上限と分割はバックエンドで行う（アダプタが対応したら、それを使う）。
  - エンジンから来た文字列（名前、ログ、資産の中身）は、そのまま言語モデルに渡る。道具の結果では、エンジン由来の文字列であることが分かる形にする（案）。
- **完了条件の案**：各道具の試験（モックのエンジン）。上限を超えた結果が切られ、続きが取れる試験。
- **規模**：M。

### NE11 画像を言語モデルへ返す

- **内容**：
  - 縮小画像（NE09）と撮影（NE18）の画像を、MCP の画像の結果（base64 と mimeType）で返す。
  - 長辺の上限で縮める（値は案）。
  - 撮影の連番は、時刻の見出しを付けて1枚の一覧に並べて返せる。言語モデルが組むエフェクトの試作（2026-10-02。ブラウザで動く小さな粒子の仕組みで、エフェクトの値を言語モデルが書き、決まった時刻の画面を並べて撮って直した）で、連番を並べた1枚が見直しに役立った。
  - 画像の処理の依存（例：`image` クレート）は、依存の追加として扱う。
- **完了条件の案**：上限を超える画像が縮む試験。一覧の並びと見出しが正しい試験。
- **規模**：S〜M。

### NE12 書き込みの道具は、編集のサービスを通す

- **内容**：
  - 書き込みの道具（値の設定、作る、複製、親の付け替え、消す、コンポーネントの付け外し、資産の編集 NE19、関数の呼び出し NE20、実行の制御）は、すべて NE02 の編集のサービスを通す。MCP の口から Bridge へ直接書かない。
  - 出どころ「言語モデル」で履歴に積む。1回の道具の呼び出しを1つのまとまりにする。
  - 名前付きのまとまりを始めて終える道具も出す（複数回の呼び出しを、1回の取り消しで戻すため）。始めたまま終えないまとまりは、時間切れか切断で閉じる。
- **完了条件の案**：言語モデルの値の設定が「言語モデル」の出どころで履歴に積まれ、画面の Ctrl+Z で戻る試験。名前付きのまとまりが1回の取り消しで戻る試験。
- **規模**：M。

### NE13 書き込みの許可

- **内容**：
  - モード：読み取りのみ（既定。作者の判断 2026-10-02）／書き込み可／書き込みごとに確認。確認のときは、エディタの画面に「何がどう変わるか」を出して、許可か拒否を選ぶ。時間切れは拒否。
  - 範囲：書き込める対象を、シーンの部分木や、資産の論理パスの接頭辞で限れる。
  - 消す・コンポーネントの取り外しは、書き込みを許すどのモードでも確認必須。読み取りのみでは拒否し、確認で書き込み禁止を上書きしない。消すと作者の履歴まで消えるため、確認には履歴への影響も示す。
  - エンジンのプロセスの起動・停止と、エンジンの設定は公開しない。
  - これは Claude Code の側の許可とは別の、エディタの側の層。
- **完了条件の案**：モードごとの試験。範囲の外への書き込みが、理由の分かるエラーで拒否される試験。読み取りのみのとき（既定）、書き込みの道具が出ないか、拒否される試験。
- **規模**：M。

### NE15 値の設定の旧値を、一度に返す

- **内容**：`object.setProperty` に、旧値を返す任意の機能を足す。新しい能力（名前は案：`object.edit.previous`）を広告するエンジンにだけ、params に `returnPrevious: true` を付け、結果に `previousValue` を入れてもらう。今の結果の定義は `additionalProperties: false` なので、能力で交渉し、古い相手には付けない。資産の値の設定（NE19）も同じ形にする。
- **理由**：言語モデルの編集には、画面のスナップショットが無い。設定の直前の読み取りは2往復になり、動いている間は値が変わりうる（NE03 の 9）。
- **NorvesLib の側**：アダプタの `objectSetProperty` で、適用の前に投影した値を `previousValue` に入れる。
- **完了条件の案**：schema、positive と negative の fixture、Rust・TypeScript・C++ の検証を同じ段で足す。モックのエンジンが返す。能力の無い相手には `returnPrevious` を付けない試験。NorvesLib のアダプタの試験。
- **規模**：S〜M（両リポ）。

### NE16 型のスキーマに、値の範囲・単位・既定値・説明を載せる

- **内容**：プロパティの定義に、任意の項目（最小、最大、刻み、単位、既定値、説明、列挙の選択肢）を足す（能力の名前は案：`schema.metadata`）。Inspector はスライダーと単位の表示に使う。言語モデルの道具の説明にも入れる。範囲の外の設定は、エンジンが拒否する。
- **NorvesLib の側**：リフレクションに範囲と単位が無いので（前提 4.2 の 2）、リフレクションの情報として足す（他のクラスでも使える形。既定値は `ClassDefaults`）。投影でスキーマに出し、値の適用で範囲を検証する。NorvesLib のロードマップの GR136（VFX システム）の「編集」の項目と同じもの。
- **完了条件の案**：schema と fixture。Inspector の表示の試験。範囲の外の設定が拒否される試験（NorvesLib）。
- **規模**：M（両リポ）。

### NE17 実行の刻みを進める

- **内容**：新しいメソッド（名前は案：`runtime.step`。params は刻みの数。一時停止中だけ受け付け、結果は進めた後の刻みの番号）と、能力（案：`runtime.step`）。Game View に「1刻み進む」のボタンを置く（人の確認にも役立つ）。撮影（NE18）の前提。
- **NorvesLib の側**：固定刻みのクロック（NorvesLib のロードマップの GR02）が前提。一時停止のまま、シミュレーションを指定の刻みだけ進める。
- **完了条件の案**：schema と fixture。モックのエンジン。一時停止していないときは拒否される試験。
- **規模**：S〜M（両リポ）。

### NE18 決定的な撮影

- **内容**：
  - 新しいメソッド（名前は案：`capture.render`）。params：視点（位置・注視点・画角、または今のカメラ）、開始点（今の刻み、または指定のオブジェクトやエフェクトを起動してから。NE20 と組み合わせる）、刻みの数と間隔（連番）、乱数の種、解像度（上限あり）、出力の名前。
  - エンジンは画像をファイルに書く。Bridge で返すのは、ファイルの場所・寸法・刻みの番号の一覧だけ（大きなデータを Bridge に載せない）。
  - 撮影は何フレームもかかるが、SDK のハンドラは同期で値を返す（前提 4.1 の 6）。そこで、受け付けの応答（撮影の ID を返す）と、完了のイベント（案：`capture.completed`。撮影の ID、ファイルの一覧、失敗の理由）の2つに分ける。エディタは完了のイベントを時間切れ付きで待ち、MCP の道具の結果として返す。
  - 書き込める場所は、エディタが決める撮影用のディレクトリの中に限る（エディタが場所を検証する）。古い撮影は、件数か日数で片付ける。
  - 同じ引数で2回撮った画像は同じになる（エンジン側の決定性）。
  - 先に `docs/memory-buffer-policy.md` に、ファイルで受け渡す方式（上限、寿命、場所の検証）を書く。
- **NorvesLib の側**：画面外への描画（指定の視点と解像度）、乱数の種の固定、刻みを進めながらの連番、PNG の書き出し、完了のイベント。決定性は、固定刻みのクロック（GR02）と再現性（GR126）の上に作る。
- **完了条件の案**：memory-buffer-policy の更新が先にある。schema と fixture（メソッドとイベント）。モックのエンジンは決まった画像を書く。場所の検証の試験。NorvesLib で、同じ引数の2回の撮影が一致する（GPU の試験。GPU の無い環境では飛ばす）。
- **規模**：L（両リポ）。

### NE19 資産の編集

- **内容**：
  - 新しいメソッド（能力の名前は案：`asset.edit`）：開く（論理パスで）、スナップショット（型のスキーマで型付け）、値の設定（NE15 と同じく旧値を返せる）、保存、閉じる・変更を捨てる。資産の変化のイベント（案：`asset.changed`）。

## 11. E0〜E3 の設計

### 接続と秘密

- MCP は既定で無効。書き込みは毎起動時に読み取りのみから始める。有効化とポートは保存できる。
- URL は `http://127.0.0.1:49770/mcp`。ポートは 1〜65535 で変更できる。衝突時は明示的に失敗し、別ポートへ黙って移らない。
- 初回有効化で OS の乱数から32バイトのトークンを生成する。`app_config_dir/mcp/mcp-token.bin` に保存し、Windows は利用者スコープの DPAPI（machine-wide の保護を使わない）、Unix は専用の `mcp/` ディレクトリ0700・ファイル0600。設定ディレクトリ全体の権限は変えない。Unix は32バイトの生値、Windows は DPAPI の保護値を保存する。破損・保護・保存・読み出しに失敗したら自動で作り直さずサーバーを起動しない。明示的な作り直しだけが既存ファイルを置き換える。
- 設定は `app_config_dir/mcp-settings.json`。`enabled` は既定 `false`、`port` は既定49770で有効範囲は1〜65535。秘密は設定ファイルへ入れない。設定の読み書きは同じディレクトリの一時ファイルと原子的置換を使い、壊れた設定は既定値へ読み替えず起動を止める。トークンの表示形式はパディング無し URL-safe Base64 とし、Settings で明示的に表示・作り直せる。ログ・エラー・操作記録に含めない。作り直しは既存認証、確認待ち、開いたまとまりを無効化する。
- `Authorization: Bearer` を全 MCP 要求で検証する。Origin が無い CLI は受け付け、存在する Origin は実際の MCP の origin との完全一致だけ許す。`null`、不正形式、外部ホストは403。Host も実際の `127.0.0.1:<port>` と照合する。広い CORS 許可を付けない。
- axum と rmcp の両方で Origin / Host の許可値を明示する。rmcp の Origin 検証は既定で無効、Host の既定許可はポートを限定しないため、既定に依存しない。旧版の `legacy_session_mode` は明示的に有効とする。
- HTTP 本体1 MiB、接続32本、実行中の通常要求16件、長寿命ストリーム8本に制限する。axum の body 制限と tokio の Semaphore / timeout で実装する。本文受信は30秒で打ち切り、受信完了後は通常要求30秒、確認を含む書き込み125秒を別に計る。確認は最大120秒だが、再照会・走査・列の待機も125秒の期限を消費し、120秒の承認時間を保証しない。要求全体のtimeoutを長寿命SSEへ適用しない。
- 切断・timeout時は、列内でまだ始めていない要求を取消し、実行中は次の操作へ進まない。既に送ったBridge要求は最大5秒の結果を確認し、判明した適用を履歴と画面へ記録する。判明しない場合は結果不明として保留し、再送しない。HTTP応答の破棄とサービスの適用成功を同一視しない。
- 現行版の `subscriptions/listen` と旧版の GET SSE は別枠で管理し、送受信のアイドル5分・最大寿命30分で閉じる。SDKのkeep-aliveだけではアイドルを延長しない。切断・期限後はクライアントが再購読し、一覧を取得し直す。再生成・無効化・ポート変更で両版のストリームと旧セッションを切断する。
- 停止時は受付を閉じ、保留を拒否し、実行中のBridge要求とHTTPストリームをキャンセルする。非同期joinの猶予は2秒で、超過した所有タスクを中止してjoinする。Tauriの同期終了フックから無期限のblocking_lockを呼ばず、終了を延期してバックエンドの停止を完了してからexitする。世代の古い応答を新しい接続へ適用しない。

### 編集と履歴

- UI と MCP の編集・取り消し・やり直し、実行制御は、有界キューを持つ1つの actor で処理する。順序は受付時に割り当てた番号。actor が履歴を所有し、Bridge / 履歴 / 許可の Mutex guard を I/O の await へ持ち越さない。
- キュー投入時だけでなく実行直前にも、接続の世代・認証改訂・能力・許可・対象範囲を照合する。処理中に切断した応答は履歴と画面に反映しない。Bridge の呼び出し一式は同じ世代の handle へ固定し、旧値の照会と設定の間で別接続へ乗り換えない。再生成前に並んだMCP要求も失効する。
- UI は旧値と旧親を発行前に捕捉し、そのスナップショットの適用改訂を渡す。actor は対象・プロパティ別の最後の適用値（親変更は旧親/新親）と改訂を持ち、捕捉後に共通列の編集があればその値へ旧値を補正する。A表示中にMCPがBを適用しUIがCを設定した場合、UIのundo先はB。補正できる古い適用値を失っている場合は再取得を求めて拒否し、古い旧値で履歴を作らない。UIの旧値未取得と JSON の `null` を区別し、従来の未取得時に書くだけの動作は保つ。MCP の旧値と旧親はキュー内で直前に照会する。エンジン自身の更新との競合は NE15 まで残る。
- UIのundo/redoは入口の実行中ガードを維持し、見えている先頭まとまりIDと履歴改訂も送る。actorは不一致・同じ先頭への重複をno-opとして扱い、連打を複数回のundoへ変えない。空・未接続時もno-op。Rustとvitestに連打試験を置く。
- 単発操作は現行どおり1件。4種の記録と NE03 の9規則を移植する。コンポーネントの付け外しは現在と同じく履歴に積まない。消す成功時は両履歴を消す。
- 複数編集の再試行位置は取り消し側とやり直し側を区別して保持する。redoの再採番は成功した記録に直ちに反映し、同じまとまりの対象ID欄（objectId/sourceId/parentId/newParentId/oldParentId/createdId）も旧ID→新IDで置き換える。値中の任意文字列は置換しない。作成→値設定、作成→子作成、複製→親変更、部分失敗後の再試行と次のundoを試験する。別まとまりへの横断置換とNE21の復元は対象外。
- 途中失敗で再試行できるのは、拒否などで未適用が確定した操作。timeout・通信断で適用の成否が不明なときは「結果不明」とし、複数まとまりの同じ操作を自動再送しない。作者が状態を確認して破棄・再接続するまで保留する。単発の失敗時の履歴破棄は現行規則を維持する。
- 名前付きまとまりのbeginはOS乱数32バイトの不透明なgroupIdを返す。正しいgroupIdを持つ呼び出しを所有者として扱い、共有トークン・自己申告のclient名からクライアント同一性を推定しない。legacy session IDは補助情報にとどめる。groupIdを他クライアントへ渡せば同じ権限を持つため、ログや画面へ秘密の実値を出さず、表示用まとまりIDは分離する。
- 最大128編集、無操作5分、全体15分で閉じる。groupIdの無い編集、別groupIdの編集、UI、undo/redo、取り消せない操作が来たら先に閉じる。Bridge切断・接続世代変更でも閉じ、旧groupIdを拒否する。人の操作を混ぜず、終わるまで列を占有しない。stateless要求の通信断だけで永続所有者を推定せず、期限・認証改訂・明示endで管理する。
- 削除・コンポーネントの付け外し・実行制御は、開いた取り消し可能なまとまりを閉じてから実行する。名前付きまとまりへ取り消せない操作を混ぜない。
- 編集サービスが適用結果と履歴要約を必ず発行する。世代、受付番号、履歴改訂番号を含め、UI は古いイベントを捨てる。購読開始時・欠落検出時はバックエンドの要約を再取得する。エンジンの best-effort イベントが無くても Inspector と Outliner を更新する。

### 道具と許可

- 道具はエディタが定めた公開メソッド一覧、接続中の実効能力、許可モードの積から生成する。能力の文字列をそのまま任意メソッドへ転送しない。入力は `bridge/spec` を埋め込み、参照を内部で解決して生成・検証する。元 schema と参照解決後の意味の一致を試験する。
- 書き込みの入力は `{params: <spec params>, groupId?: <opaque>}` の外枠を持つ。意味の一致・unknown field拒否はparams部分へ適用し、外枠も別schemaで検証する。ページング・ログ・履歴・まとまりは独自schemaを持つ。Bridgeに渡すのは検証済みparamsだけで、cursor/groupId/許可情報は送らない。
- 道具に必要な能力の組を明示する。値設定の旧値取得はobject.edit＋object.query、親変更の旧親取得と部分木の許可はscene.queryも必要。componentIdの所属はobject snapshotで解決する。範囲判定の走査は最大2000ノード/200スナップショット/合計2MiB/5秒で、不足能力・未解決・上限超過は拒否する。
- 読み取りは状態・能力・ツリー・スナップショット・型・資産一覧と解決・最近のログ・縮小画像。ツリーは深さ優先の平坦な項目（id/parentId/depth/元ノードの表示属性）として1応答256 KiB、1頁200項目に分ける。保持する読み取りスナップショットは合計16 MiBでLRUの古いものを追い出し、そのcursorは期限切れとして拒否する。cursorは世代とスナップショットへ結び、期限5分。16MiB超の単一snapshot・256KiB超の単一項目は明示エラー。
- エンジン由来の名前・説明・ログ・値は、出典が分かる結果のデータ領域に入れる。道具の指示や権限判断に使わない。schema の説明はリポジトリの仕様から使う。
- バックエンドは接続後に能力log.streamがある場合だけlog.subscribeを世代固定で1回発行する。MCP無効・UI不在でも購読し、結果を表示状態に持つ。空でないsubscriptionIdがあれば購読成功とし、無い応答は不適合と表示してIDを捏造せずunsubscribeを送らない。受信ログ自体は世代を検査して保持する。明示切断は同じhandleのlog.unsubscribeを最善努力で行い、世代変更・終了では購読タスクを取り消す。古い世代のackやイベントを捨てる。ログは世代別連番で1000件か合計2MiBの先に達した方で古い順に落とし、時刻と連番・保持範囲と欠落を返す。
- PNG の縮小画像は既存の Bridge 上限（640x360・256 KiB・毎秒1回）を全入口で共有する。UI/MCP同時要求は同じin-flight取得へ合流し、取得後1秒以内は世代別の最新PNGを再利用する。PNGを検証し、宣言寸法と実寸を照合してから返す。汎用画像ヘルパーは長辺縮小と時刻見出し付き一覧を備えるが、撮影要求・ファイル受け取りの公開道具はE4。
- 画像ヘルパーは最大16枚、入力の各辺4096、画素数16777216、復号と合成の作業領域合計128 MiB、一覧の長辺2048、出力PNG 2 MiBに制限する。寸法上限を復号前に確認し、CPU処理は有界の blocking worker へ渡す。見出しは数字と記号の小さな固定字形で描き、外部フォントを配布しない。
- 書き込みは値の設定、作成、複製、親変更、削除、コンポーネントの付け外し、undo/redo、play/pause/stop。いずれも共通サービスへ渡す。`asset.reloadManifest`、プロセスの起動・終了、エンジン設定、任意ファイルアクセスは MCP に出さない。
- play/pause/stop は状態を変える道具として許可を通すが、履歴には積まない。シーン部分木に限定した許可だけでは、エンジン全体の実行制御を許さない。MCP の実行制御には全体の範囲が必要。
- 書き込み可能なシーン範囲は選んだ根の部分木。componentId は所属オブジェクトへ解決する。親変更は元と先、複製は元と先、削除は子孫を含めて検査する。undo/redo は対象のまとまり全体を検査する。資産の接頭辞による編集許可の実装は NE19 の段で行う。
- MCPのundo/redoは全入口で共有する先頭まとまりを対象にし、人のまとまりも対象になり得る。出どころと全対象を結果と確認へ示し、範囲の検査を省略しない。部分失敗保留中は通常undo/redoとplay/pause/stopも拒否し、Ctrl+Z/Y・ボタンは無効。状態の読み取り、再試行、破棄、接続終了だけを受け付ける。
- 確認には道具・対象・変更前後・取り消し可否・履歴への影響を出す。確認待ちは列の外で120秒、HTTP切断でも取り下げる。許可後に世代・認証改訂・対象・旧値・範囲・許可設定が変わったら再確認が必要。undo/redoは先頭まとまりID/履歴改訂、deleteは全履歴破棄の影響も照合する。確認IDは指定要求に一度だけ使える。画面にはパネルを閉じていても通知と待ち件数を出し、クリックで確認パネルを開く。CLI/MCPから承認できない。
- 旧版のrmcpはHTTP切断だけでは要求を取り消さないため、エディタが要求IDごとのcancel tokenをHTTP応答の破棄へ結び付ける。現行版のSDKキャンセル経路とともに、両版で未承認要求が切断後に適用されないことを試験する。
- 必須確認は道具名だけで判定せず実際の操作へ適用する。MCP の undo が作成/複製の逆操作として delete を行う場合も、削除対象と履歴への影響を示して確認する。UIのundoは従来の動作を維持する。
- 操作記録は拒否・失敗・一部成功・結果不明を区別して残し、道具結果も適用の成否不明と自動再送禁止を伝える。時刻、道具、対象、要約、結果、表示用まとまりIDを記録し、トークン・所有者groupId・資産本文・巨大値を記録しない。`app_log_dir/mcp-operations.jsonl` は1MiB×2世代。UI履歴リンクの取り消しも共通列を通る。

### 接続と許可

- 現行stateless版ではクライアント別の要求ID空間がない。同じIDの実行中要求は後着が409となり、完了後の遅延取消が別クライアントの同じIDを取り消す場合がある。接続元間でも要求IDを重複させず、完了済み要求へ取消を送らない。旧版はセッションと数値/文字列IDを区別する。
- Enabledでも、列待ち中に旧値・範囲・履歴改訂などが変われば改めて画面確認を求める。画面を見ていない場合は期限切れになる。許可変更は旧要求を取り下げ、同じ要求の再確認を継続しない。旧改訂の確認だけを取り下げるので、新改訂で登録された確認は保護される。
- 確認コマンドはバックエンドでmainラベルを検査する。Tauri capabilityによる確認専用権限の追加分離は未対応。サーバー停止中はcontrol lockにより承認/拒否の受付が最大2秒待たされる。
- 名前付きまとまりは128編集、無操作5分、全体15分で閉じる。同値が受理されただけでは無操作期限を延長しない。履歴に積まれた編集だけが延長する。切断、接続世代交替、許可失効、UI操作などの境界で旧groupIdは利用できなくなる。
- redoの認可は履歴の実行順で検査し、同じまとまりの先行Create/Duplicateが生成するIDだけを後続の対象・親として扱う。逆順参照、未知ID、既存ノードIDとの衝突、範囲外の親・複製元・移動元・移動先を拒否する。親を省略した複製先と、履歴に保存した親とは異なる現在の移動元も検査する。既存対象のcomponent所属・現在値と範囲は承認後と列内でも同じ規則で再照合する。再作成前の対象には現在値がないため、確認表示で保存値を現在値として代用しない。component IDとの衝突検査は所属照会で取得した範囲に限られ、全component IDとの重複検査は保証しない。再作成後の書き込み対象は新IDに置換する。衝突の説明は「シーンツリーに重複IDがある」となる。
- 部分木取得の根の `parentId` はnullで、元のシーン上の親を返さない。cursorは世代固定で、再接続後は再取得が必要。旧世代の遅い読み取りがsnapshot storeの世代を戻し、現行cursorまで失効させる場合がある。古い結果は返さないが、有効だったページの取り直しが必要になる。

### 適用結果と操作記録

- `result` は要求の結果分類、`outcome` は確認できた適用結果を示す。未送信の `notApplied`、エンジンの確定拒否 `rejected`、確認済み `applied` / `partial`、結果不明 `unknown` を区別する。HTTP取消後にactorが確定した結果は、同じ表示用requestIdへ反映する。自動再送は行わない。
- 開始済み書き込みへの `notifications/cancelled` は、現行版では `outcome=unknown` / `operationResult=unknown` と表示IDを返す。旧版では要求別SSEがJSON-RPC結果なしで終了する。どちらも編集actorはBridgeの結果を保持し、同じ操作記録を `applied` / `rejected` へ確定する。`result` も `unknown` から `success` / `rejected` へ更新されるため、取消理由の独立した履歴ではない。未送信の列待ち取消は `result=cancelled` / `outcome=notApplied` として区別する。
- 通常書き込みの列に入る前の拒否は確定として記録する。`actorFinished` は後続actor結果を待たないことも含む。開始済みの取消/失効は結果確定まで未適用とは断言しない。送信直前の世代/認証変化が `unknown` になる安全側の分類が残り、履歴の不明印と一致しない場合がある。
- 単発MCP undoの確定拒否も、完了0件の再試行可能な保留になる。通常UI編集と実行制御を止め、画面の状態確認・再試行・破棄から復旧する。破棄は適用済み変更を自動で戻さず、残存状態を通知する。
- requestIdには起動ごとの乱数識別を含む。JSON-RPCのクライアント要求IDとは別で、再起動後も操作記録のIDを使い回さない。トークン、確認ID、所有者groupId、要求本文は記録しない。
- 記録は読み取りと書き込みを合わせた最新500件。大量の読み取りで書き込みのリンク元が画面から押し出される。ファイルは1MiB×2世代で実行中にローテーションする。更新ごとに最大500件のsnapshotを通知し、async actor上で同期ファイル保存するため、高頻度利用の通知量と保存待ちが残る。
- 一部の期限分類はエラー説明の「期限」/「timed out」に依存する。別の期限を含む拒否が `timedOut` になる場合と、列開始直前の期限切れが認証失効の説明になる場合がある。終了理由だけから適用の有無を推定せず、outcomeと履歴を確認する。
- AIの操作パネルの許可エラーは確認パネルと重複表示される場合がある。undo道具の記録のリンクは取り消したまとまりを指し、そのまとまりがredoで先頭へ戻ると再度取り消せる。履歴の再取得が失敗した後はパネルを開き直すまでリンクを無効にする。
- 旧来の `EditService::new_with_app` / `new_with_app_and_authorization`、既定読み取り文脈を使う組み立て入口は残る。本番と実mock受入は `McpServices::new` に統一されている。旧入口の整理は未対応。

受入スクリプトはPowerShell 5.1でも標準出力をUTF-8へ明示的に揃える。
