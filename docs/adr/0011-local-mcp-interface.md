# 0011: NorvesEditor にローカル MCP の口を設ける

状態: 承認済み（2026-10-03、E0〜E3）

## 背景

言語モデルから、接続中のエンジンの状態・型・シーンを読み、許可された編集を行いたい。
エンジンへ別接続する方式は単一接続の SDK と衝突し、エディタの履歴と許可を通らない。
エンジン固有の道具を作ると汎用エディタの境界を失う。

## 決定

Rust バックエンドへ公式 `rmcp` の Streamable HTTP サーバーを組み込み、
`127.0.0.1` だけに bind する。既定は無効、ポートは49770、Settings で変更する。
MCP の通信は Bridge の封筒へ混ぜず、エディタのサービスを呼ぶ入口にする。
SDK が扱う現行2026-07-28と legacy 2025-11-25 の経路を、それぞれ検証する。
現行版は購読filterとlistenを実装しSubscriptionSinkへ通知する。旧版はセッションpeerへ通知する。
試験はDiscover/Initializeを明示し、SDK既定の購読・Origin検証へ依存しない。

全要求を Bearer トークンで認証する。トークンは OS 乱数32バイトから生成し、
`app_config_dir/mcp/mcp-token.bin` へ保存する。Windows は利用者スコープの DPAPI、
Unix は専用mcpディレクトリ0700とファイル0600を使う。保存・保護に失敗したら起動しない。
表示・作り直しはローカルの Settings だけで行い、秘密をリポジトリやログへ書かない。

Origin がある場合は設定した MCP origin との完全一致を検証し、不正なら403。
Origin の無い CLI は認証を通して受け付ける。Host も固定の loopback authority と照合する。
HTTP 本体・並行処理・接続・時間・画像の上限を付ける。終了・無効化・ポート変更・
トークン再生成で受付と保留を閉じ、所有するタスクを終了させる。
具体的上限は要件11章に定め、通常要求と確認待ち、長寿命ストリームを分ける。
現行listen/旧GET SSEの期限と本数を管理し、再生成で両版を切断する。実行直前にも認証改訂を検査する。

道具の一覧はエディタの公開一覧と接続中の実効能力から作る。Bridge メソッドの入力定義は
リポジトリの params schema を使い、外部参照を埋め込み定義へ解決する。入力と結果を検証し、
ネットワークや任意ファイルから schema を取得しない。書き込みはparamsと任意groupIdの外枠を使い、
specとの一致はparams部分で試験する。エディタ独自引数をBridgeへ送らない。
名前付きまとまりはbeginで発行した秘密のgroupId所持で管理し、表示用IDを分ける。
接続・能力・許可が変われば一覧を更新し、対応する通知経路で知らせる。

書き込みは毎起動時に読み取りのみ。書き込み可・都度確認のモードとシーン部分木の範囲を、
エディタ側で検査する。削除とコンポーネントの取り外しは、書き込みを許すどのモードでも
ローカル画面の確認を必須にする。読み取りのみを確認で解除できない。
確認は要求・世代・変更前後・許可/認証改訂に結び付け、期限・状態変更・HTTP切断で無効にする。
undo/redoは先頭IDと履歴改訂、deleteは履歴破棄の影響も再照合する。閉じたパネルには通知で案内する。
確認待ちが編集列を占有しないよう、許可後に再検証して共通列へ入れる。
MCP のundoが逆操作のdeleteを行う場合も、この削除確認を通す。

MCP の編集・undo/redo・play/pause/stop は ADR 0010 のサービスを通す。
実行制御は許可と操作記録を通すが取り消し履歴へ積まない。部分木だけの許可で全体の実行を変えない。
エンジンのプロセスの起動・終了とエンジン設定は公開しない。
MCPは人のまとまりも共有先頭としてundoし得るため、出どころを表示し全対象を検査する。
部分失敗保留中は新編集・通常undo/redo・実行制御を拒否する。

エンジン由来の文字列は結果のデータとして示し、道具の指示や権限の根拠にしない。
読み取り結果とログを有界にし、続き・欠落・出典を明示する。縮小画像は既存のPNG・
640x360・256 KiB・毎秒1回の契約と最新1秒のキャッシュを共有する。
バックエンドが接続世代ごとにlog.subscribeを行い、UI不在でもログを保持する。
撮影・資産編集のプロトコル追加は E4。

## 帰結

新しい待ち受けと認証・タスク寿命がバックエンドに加わる。HTTP/SDK/schema/画像処理の
依存は [要件12章](../mcp-and-edit-layer-requirements.md) の範囲で導入する。
MCP はアプリを有効化した利用者がクライアントを設定して接続する。外部バイナリと
JS のネットワーク・shell・dialog 権限を追加する必要はない。
言語モデルの出力品質は作者が判断し、エディタは許可・履歴・適用結果・操作記録を保証する。

stdio の子サーバー方式は、既に動いているエディタとの別の制御経路が必要になるため採らない。
エンジン直結の MCP は履歴と許可の所有を分散させるため採らない。

## セキュリティ規約との整合

アルファの遠隔接続無効は維持し、MCP も loopback のみとする。Bridge の接続先・
プロセス所有者・Tauri capabilities の境界は変えない。HTTP の認証は Tauri の IPC 許可とは別に設ける。
管理外の agent-guide の同期は MyWorkflow の正本を編集して再展開する。

## 検証

無効時のポート閉鎖、loopback 固定、不正 Origin の403、認証拒否、トークン再生成、
bind 失敗の表示、停止後のタスク終了、道具の能力・schema一致、モード・範囲・確認、
編集イベントによる表示、モック相手の実 HTTP 往復を試験する。
