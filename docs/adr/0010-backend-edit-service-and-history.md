# 0010: 編集と履歴を Rust バックエンドで所有する

状態: 承認済み（2026-10-03、E0〜E3）

## 背景

現行の取り消し履歴は TypeScript の store が持ち、画面のフックが逆操作を送っている。
画面外の MCP が編集すると、同じ履歴への記録と同時操作の順序を保証できない。
エンジンは一度に1つのエディタ接続を受け付けるため、MCP はエディタの接続を共有する。

## 決定

Rust の編集サービスが履歴と有界の実行列を所有する。画面の Tauri コマンドと MCP の道具は、
このサービスへ編集・取り消し・やり直し・実行制御を渡す。受付番号で順序を定め、
1つの actor が1件ずつ実行する。actor は履歴を直接所有し、I/O 中に状態ロックを保持しない。

Bridge の処理は接続の世代と dispatcher handle を固定して行う。切断・終了・再接続で
履歴と保留を無効にし、古い応答を履歴へ積まない。ワークスペースを閉じるだけでは履歴を消さない。
停止時は受付を閉じ、保留を拒否し、Bridge要求をキャンセルする。2秒の猶予後は所有タスクを中止してjoinする。
Tauriの同期終了フックでは終了を延期し、非同期の停止を終えてからexitする。

現行の4種の記録と NE03 の9規則を維持する。画面は旧値・旧親と適用改訂を発行前に捕捉する。
actorがその後に同じ対象へ適用した値を持つ場合は、そちらを旧値に使う。画面がAのまま、
列でMCPがB、画面がCを適用した場合、画面のundoはBへ戻す。後続liveイベントだけでは補正しない。
未取得とnullを区別する。MCPは同じ列の中で、設定直前にスナップショットを読む。
エンジン自身の更新による旧値のずれは、旧値を設定結果で返す NE15 まで残る。
値の同値判定はJSON.stringifyのキー順・数値・負のゼロの規則を保つ。

画面のundo/redoは実行中ガードと先頭まとまりID/履歴改訂を使う。不一致や重複はno-opとし、
キーリピートを複数回のundoに変えない。空・未接続時もno-opにする。

履歴の単位は名前・出どころ・時刻を持つまとまり。画面の単発操作は現在と同じ粒度とする。
単発の取り消し失敗では記録を捨てる。複数編集の途中失敗では成功位置と未処理部分を保持し、
新しい書き込みを拒否して再試行・破棄を受け付ける。再試行で成功済みの操作を繰り返さない。
通常の編集が失敗した場合は打ち切り、成功した分だけを履歴に残す。
複数まとまりで timeout / 通信断の結果が不明な操作は再送しない。
未適用が確定した拒否だけを再試行し、結果不明は作者の確認と破棄・再接続で解消する。
保留中は通常undo/redoと実行制御も拒否し、画面ではキーとボタンを無効にする。
redoで新IDが出たら同じまとまりの対象ID欄を置換し、部分失敗後の再試行にも引き継ぐ。
別まとまりのIDや値中の任意文字列は置換しない。

名前付きまとまりはbeginが返す256 bitの不透明groupIdの所持を所有権とする。
共有認証トークンやclient名では別クライアントを識別しない。groupIdを持たない編集とUI、
undo/redo、非取り消し操作が入る前に閉じる。表示用のまとまりIDは秘密のgroupIdと分ける。
まとまり全体で列を占有しない。128編集・無操作5分・全体15分・認証改訂・無効化・接続世代変更で閉じる。
削除・コンポーネントの付け外し・実行制御は取り消し履歴に積まず、開いたまとまりを先に閉じる。
削除成功時に履歴を全部消す規則は維持する。実行制御と MCP の結果は別の操作記録へ残す。

適用結果と履歴要約は編集サービス自身が Tauri イベントとして出す。画面は世代・受付番号・
履歴改訂を確認して表示を更新する。購読開始時と欠落検出時には要約を取得し直す。
エンジンの best-effort イベントに、MCP の編集表示を依存させない。

## 帰結

UI の履歴は表示用の要約になり、旧値や逆操作の正本を保持しなくなる。
同時編集・取り消し・再接続の試験が Rust へ移る。Ctrl+Z / Ctrl+Y とボタンの振る舞いは維持する。
部分失敗の進行位置、キューの上限、キャンセル、イベント再同期がバックエンドの責任になる。
削除と取り外しの復元、依存する別まとまりの ID 書き換え、シーンの保存は別の要件である。

UI の履歴を残して MCP から更新する方式は、複数画面・画面不在・同時操作に正本が分散するため採らない。
エンジン側に履歴を移す方式は、汎用プロトコルと全アダプタの変更が必要になるため E0〜E3 の移行に使わない。
